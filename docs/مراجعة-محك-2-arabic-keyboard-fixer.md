# مِحَك — مراجعة ثانية: arabic-keyboard-fixer

> **النوع المكتشف:** تطبيق (أداة ويب أوفلاين، بلا خادم، بلا حلقة رسم) — طُبّق رابرك التطبيقات.
> **نطاق المراجعة:** كل ملفات المستودع (20 ملف، ~3,600 سطر شاملة التوثيق). شُغّلت الاختبارات (`npm test` → 29/29 ناجحة) و `eslint` (نظيف)، وجُرّب المحرّك فعليًا على ~40 مدخل يدوي، والنتائج المذكورة أدناه منسوخة من التشغيل لا مستنتجة.
> **السياق:** هذي المراجعة الثانية بعد تنفيذ خطة الإصلاح في PR #6. المراجعة الأولى أعطت المشروع تقريبًا 6.5/10؛ الفرق واضح وحقيقي.

## 1. نظرة عامة سريعة

أداة ويب تصحّح النص المكتوب بتخطيط لوحة مفاتيح خاطئ (عربي ↔ إنجليزي): تحلّل النص كلمةً كلمة، تقترح التحويل مع نسبة ثقة، وتسمح بالتطبيق أو النسخ مع تراجع (undo). تعمل كـ PWA أوفلاين على GitHub Pages.

- **البنية:** `js/converter.js` (محرّك نقي بلا DOM — جداول التخطيط، التحويل، التقييم اللغوي، الكشف) + `js/app.js` (الواجهة، i18n، السجل، الاختصارات) + `locales/*.json` + `service-worker.js`.
- **التقنيات:** JavaScript ES modules بدون إطار ولا تبعيات تشغيل. `eslint@9` كتبعية تطوير فقط. Node ≥18 للاختبارات. GitHub Actions للاختبار والنشر.
- **الحجم:** 387 سطر محرّك، 686 سطر واجهة، 570 سطر CSS، 206 سطر اختبارات.

## 2. المراجعة التقنية والهندسية (45%)

### 2.1 البنية المعمارية وفصل المسؤوليات — **8/10**

فصل المحرّك عن الواجهة تم صح: `converter.js` ما يلمس `document` ولا `t()`، والاختبارات تستورده مباشرة. هذا أكبر تحسّن عن المراجعة السابقة.

الباقي: `app.js` ملف واحد من 686 سطر يجمع i18n + السجل + الثيم + التوستات + الاختصارات. منظّم بفواصل واضحة، فما هو عائق الآن، لكنه المرشّح الطبيعي للتقسيم لو كبر المشروع (`history.js`، `i18n.js`).

### 2.2 قابلية القراءة والصيانة — **8/10**

التعليقات تشرح «ليش» لا «وش» — مثال ممتاز في `converter.js`:

```js
/**
 * Both layouts map every Latin letter onto *some* Arabic letter, so "how many
 * characters are Arabic" cannot tell a real word from noise — it rated the
 * English phrase "carrot pizza" at 92%. ...
 */
```

الثوابت (`MIN_SCORE`, `MARGIN`, `SWEEP_RATIO`, `MIN_PARTIAL_LENGTH`) مسمّاة ومشروحة. الدوال قصيرة. مطوّر جديد يفهم المحرّك في ربع ساعة.

### 2.3 التكرار (DRY) و Code Smells — **7/10**

- `converter.js` — جدول `qwertyToArabic102` (معطوب باعتراف التعليق) ما زال يُشحن للمستخدم ويُصدَّر من الوحدة، وهو كود ميت خلف `ENABLE_102 = false`. الأفضل نقله إلى `tests/fixtures/` أو فرع مستقل حتى يُصلَح، بدل شحنه في كل تحميل.
- `app.js` — نمط «احفظ القيمة السابقة → عدّل → توست بزر تراجع» مكرر أربع مرات (`applySuggestion`، `swapDirectionBtn`، `Alt+K`، `clearHistoryBtn`). دالة `withUndo(previous, restore, message)` تختصرها.

### 2.4 معالجة الأخطاء والحالات الحدّية — **6/10** ⬅ أضعف نقطة

الأخطاء المبتلعة مقصودة وموثّقة (`localStorage` في وضع التصفح الخاص)، و `detectInput` ملفوفة بـ `try/catch` بعرض رسالة للمستخدم. الحالات الحدّية في **منطق الكشف** هي مصدر العيوب المتبقية:

**(أ) 🟠 كلمتان: واحدة صحيحة وواحدة مقلوبة ← تُقلب الاثنتان.** مؤكَّد بالتشغيل:

```
"شكرا اثممخ"   => english: "a;vh hello"
"مرحبا اثممخ"  => english: "lvpfh hello"
"hello g]d"    => arabic101: "اثممخ لدي"
```

بينما `"أنا بخير اثممخ"` (ثلاث كلمات) يعطي الصحيح `"أنا بخير hello"`. السبب في `buildSuggestion()`:

```js
const sweep = accepted.length / convertible.length >= SWEEP_RATIO; // 1/2 >= 0.5 → true
...
if (sweep) {
    applied = convertible;   // يقلب حتى الكلمة اللي كانت صحيحة
```

مع كلمتين فقط، كلمة واحدة مقبولة تكفي لـ«الكنس» الكامل، فتُدمَّر الكلمة العربية السليمة. وهذي بالضبط الحالة الشائعة («شكرا» ثم كلمة مكتوبة بالتخطيط الغلط). الحل — لا تكنس كلمة تقرأ بشكل سليم في لغتها الأصلية:

```js
if (sweep) {
    applied = convertible.filter(r => r.accepted || scoreSource(r.token) < MIN_SCORE);
}
```

(أو اجعل الشرط `>` بدل `>=`، لكن هذا يكسر حالة كلمتين مقلوبتين نصفهما فقط مقبول.) وأضف الحالات الثلاث أعلاه لقسم «it must stay quiet» في الاختبارات.

**(ب) 🟡 اختصارات إنجليزية قصيرة تُقترح كعربي عند حد القبول بالضبط:**

```
"PDF" => arabic101: "حيب" (28)
"ahs" => arabic101: "شاس" (28)
```

28 = `MIN_SCORE` بالضبط. المسار: كلمة واحدة ⇒ `sweep` صحيح ⇒ لا يمر على فلتر `MIN_PARTIAL_LENGTH`. ليس ضارًا (اقتراح فقط، لا تطبيق تلقائي)، لكنه ضجيج. الحل: كلمة كلها أحرف كبيرة (`/^[A-Z]{2,5}$/`) تُعامل كاختصار ولا تُحوَّل، أو ارفع الحد لنص من كلمة واحدة.

**(ج) 🟡 طبقة Shift ناقصة رموزًا عربية فعلية.** `qwertyShiftToArabic101` لا يحتوي `P → ؛` ولا `I → ÷` ولا `O → ×` ولا `U → ‘`. النتيجة المؤكَّدة:

```
convertToArabic('P')  => 'ح'   // المفروض '؛'
convertToEnglish('؛') => '؛'   // يمر دون تحويل
```

الفاصلة المنقوطة العربية شائعة في النصوص الرسمية. الحل: أضف `'P': '؛', 'I': '÷', 'O': '×', 'U': '‘'` (تحقق منها من MSKLC كما فعلت مع الباقي)، والاختبار `layoutProblems` سيحرسها تلقائيًا من التكرار.

**(د) 🟠 سباق (race) بين الـ debounce واختصار Ctrl+Enter.** في `app.js`:

```js
if (currentSuggestions && currentSuggestions[0]) {
    e.preventDefault();
    applySuggestion(currentSuggestions[0]);
}
```

`currentSuggestions` يتحدّث بعد 120ms من آخر حرف. لو كتب المستخدم حرفًا وضغط Ctrl+Enter فورًا، يُطبَّق اقتراح محسوب من النص **القديم** ويضيع الحرف الأخير (التراجع يرجعه، لكن المستخدم غالبًا ما ينتبه). كل اقتراح يحمل `original`، فالحل سطر واحد:

```js
if (currentSuggestions?.[0]?.original !== textInput.value) detectInput();
```

قبل القراءة، في معالج Ctrl+Enter و Alt+C معًا.

### 2.5 الأداء واستهلاك الموارد — **8/10**

يوجد اختبار أداء صريح: 50 ألف حرف في أقل من ثانية — نجح. الـ debounce بـ 120ms معقول. المعاينة مقصوصة على 500 حرف (`PREVIEW_LIMIT`) فلا يُحقن نص ضخم في DOM. الملاحظة الوحيدة: `scoreSource(text)` على المستند كاملًا يُحسب داخل `buildSuggestion` لكل اتجاه — تكلفة مضاعفة صغيرة لا تستحق التعديل الآن.

### 2.6 الاختبارات — **7/10**

29 اختبار، تستورد الوحدة مباشرة، وفيها فكرة ممتازة: `layoutProblems()` تتحقق من أن الجدول «تقابل» (bijection) بلا تكرار ولا حرف غير قابل للكتابة — حارس بنيوي لا يحتاج مرجعًا خارجيًا. اختبار رجوع (round-trip) واختبارات «يجب أن يسكت» لـ SQL والإنجليزية العادية.

الناقص:
- لا توجد حالة مختلطة **من كلمتين** — لهذا مرّ عيب 2.4 (أ).
- لا توجد أي اختبارات لـ `app.js` (السجل، TTL، التراجع، الاختصارات). اختبار Playwright واحد لمسار «الصق ← طبّق ← تراجع» يغطي أهم سلوك واجهة. (Chromium متوفر في بيئة CI عادةً.)

### 2.7 التوثيق — **8/10**

README عربي فعلي ومفيد، يشرح سبب تعطيل 102 بصراحة نادرة. `CONTRIBUTING.md` مفصّل. ملاحظة صغيرة: رقم الإصدار مكرر يدويًا في ثلاثة أماكن (`package.json` 1.2.0، الفوتر في `index.html`، و `locales/*.json` `labels.footer`) — سهل أن ينسى أحدها.

### 2.8 اتفاقيات التسمية ونمط موحّد — **9/10**

camelCase متسق، ثوابت UPPER_SNAKE، `.editorconfig` و ESLint بقواعد معقولة (`eqeqeq`، `prefer-const`). لا ملاحظات جوهرية.

**متوسط القسم:** (8 + 8 + 7 + 6 + 8 + 7 + 8 + 9) ÷ 8 = **7.6/10**

## 3. المظهر والتصميم وتجربة المستخدم (30%)

### 3.1 الاتساق البصري — **8/10**

كل الألوان متغيرات CSS في `:root` مع نسخة فاتحة كاملة. خط واحد للواجهة. التصميم وظيفي ومتّسق.

### 3.2 سهولة الاستخدام والتنقل — **8/10**

المهمة الأساسية = لصق + نقرة واحدة. زر ⇄ «إجبار التحويل» حل ذكي لما يسكت الكاشف. التراجع بدل نوافذ التأكيد خيار صحيح. عرض «غُيّرت X من Y كلمات» يوضّح للمستخدم وش بيصير قبل التطبيق.

### 3.3 الاستجابة — **8/10**

breakpoint عند 600px، الأزرار `min-height: 44px` و `.icon-btn` 44×44. ما لقيت شيء يفيض على الجوال من الكود.

### 3.4 العربية و RTL — **7/10**

إيجابيات فعلية (لا مجرد `dir="rtl"`):
- `dir` و `lang` يتبدّلان مع اللغة من `loadLocale()`.
- `inset-inline-start` في `.skip-link` بدل `left`.
- `dir="auto"` على `textarea` وعلى محتوى الاقتراحات والسجل — صحيح لأن النص مختلط بطبيعته.
- `.shortcuts-hint` مثبّت LTR عن قصد وموثّق.
- الأرقام لاتينية عن قصد (`ar-SA-u-nu-latn`) — قرار متسق.

السلبي: `css/styles.css` — الـ `textarea` يستخدم:

```css
--font-mono: 'Courier New', 'Segoe UI', Tahoma, 'Noto Sans Arabic', monospace;
```

على ويندوز، Courier New فيه حروف عربية فيُستخدم هو للعربي — شكلها رديء وغير مريح للقراءة، وهذا هو المكان اللي يقرأ فيه المستخدم نصه العربي. الحل: اجعل `textarea` و `.suggestion-content` تستخدم `var(--font-ui)`، واترك المونو لـ `kbd` فقط.

### 3.5 إمكانية الوصول — **8/10**

رابط تخطٍّ، منطقة `aria-live` بملخص قصير بدل إعادة قراءة اللوحة، `aria-label` مترجمة على كل الأزرار، `focus-visible` واضح، `prefers-reduced-motion` محترم، عناصر السجل قابلة للتشغيل بـ Enter/Space.

ملاحظتان صغيرتان:
- `app.js` — `historyToggle.setAttribute('aria-checked', ...)` على `<input type="checkbox">` أصلي: زائد ويخالف توصية ARIA in HTML (لا تضف ARIA على عنصر يعبّر عن حالته أصلًا). احذف السطر.
- `textarea:focus { outline: none; }` ويعتمد على تغيّر لون الحد فقط — مقبول لأن الحد 2px، لكن الأضمن إبقاء `outline` مع `outline-offset`.

### 3.6 التغذية الراجعة — **7/10**

توستات للنسخ/الفشل/التطبيق/المسح، رسالة تجاوز الطول لا تُحذف تلقائيًا (إصلاح ممتاز عن السابق)، حالات فارغة مختلفة لـ «لا يوجد نص» و«لا اقتراحات».

ينقص:
- سباق Ctrl+Enter (2.4 د) يطبّق شيئًا غير اللي يشوفه المستخدم.
- التراجع عن «تطبيق» يرجع النص لكن **يترك قيد السجل**، فالسجل يعرض تصحيحًا تراجع عنه المستخدم. الحل في `applySuggestion`: في `onAction` احذف `history[0]` إذا كان هو القيد المضاف للتو.
- ثقة 28% تُعرض كاقتراح بنفس شكل ثقة 100%. تمييز بصري بسيط (لون باهت أو عبارة «احتمال ضعيف») تحت 50% يساعد المستخدم يقرر.

**متوسط القسم:** (8 + 8 + 8 + 7 + 8 + 7) ÷ 6 = **7.7/10**

## 4. المراجعة الأمنية (25%)

**طبيعة المشروع:** أداة أوفلاين بالكامل، لا خادم، لا مصادقة، لا شبكة إلا تحميل ملفات المشروع نفسه. التقييم على النقاط المنطبقة فقط.

| النقطة | الحكم | الدرجة |
|---|---|---|
| المفاتيح والأسرار | لا أسرار، لا `.env` في المستودع | 10/10 |
| الحقن | لا يوجد `innerHTML` ولا `eval` ولا `insertAdjacentHTML` في أي ملف (مُتحقق بـ grep). كل الإدراج عبر `textContent` / `el()`. حتى نصوص الترجمة تُبنى كعناصر | 10/10 |
| التحقق من المدخلات | حد 50 ألف حرف بلا حذف لنص المستخدم، `loadLocale` يقيّد اللغة بقائمة بيضاء، `readStoredHistory` يتحقق من شكل كل قيد | 9/10 |
| الصلاحيات والمصادقة | لا ينطبق — بلا خادم | — |
| البيانات الحساسة | السجل معطّل افتراضيًا ومشروح السبب (كلمات المرور)، TTL 24 ساعة، زر حذف البيانات القديمة | 9/10 |
| الاعتماديات | صفر تبعيات تشغيل | 9/10 |
| CSP والترويسات | CSP عبر `<meta>` صارم (`default-src 'self'`, `object-src 'none'`, `base-uri 'none'`) | 8/10 |

الملاحظات:

- 🟡 **البيانات الحساسة** — `app.js`: الـ TTL يُطبَّق عند **القراءة** فقط (`readStoredHistory`). لو فعّل المستخدم السجل ثم ما رجع للموقع، تبقى النصوص في `localStorage` للأبد. لا حل كامل بلا خادم، لكن التوثيق في الواجهة («يُحذف بعد يوم») يوحي بحذف فعلي. عدّل الصياغة إلى «يُتجاهل ويُحذف في الزيارة التالية بعد يوم»، أو استخدم `sessionStorage` كخيار افتراضي عند التفعيل.
- 🟡 **الاعتماديات** — `.github/workflows/test.yml` يثبّت `eslint@9` بلا قفل إصدار، و npm نفسه يحذّر: `eslint@9.39.5: This version is no longer supported`. أداة تطوير فقط، لا خطر على المستخدم؛ حدّث إلى eslint 10 وأضف `package-lock.json` لثبات CI.
- 🟡 **CSP** — `frame-ancestors` لا يعمل داخل `<meta>`، و GitHub Pages لا يسمح بترويسات مخصّصة، فالحماية من clickjacking غير ممكنة هنا. أثرها شبه معدوم لأداة بلا أفعال حساسة — يُذكر للعلم لا للإصلاح.
- 🟡 **Service Worker** — `service-worker.js` بنمط stale-while-revalidate يعني أن النشر الجديد يظهر في **الزيارة الثانية** لا الأولى، ورفع `CACHE = 'akf-v5'` يدوي. ليس ثغرة، لكن لو نُشر إصلاح أمني يتأخر وصوله. اربط اسم الكاش بالإصدار في `package.json` أو أضف إشعار «تحديث متاح».

**متوسط القسم (النقاط المنطبقة):** (10 + 10 + 9 + 9 + 9 + 8) ÷ 6 = **9.2/10**
